| HB-PERIOD-001 | `TimeUnit.parse()` / WEEK | Canonical week periods cannot be parsed. | Parsing `2024-W01` raises `ValueError: Unsupported token: WW` because `TimeUnit.parse()` passes `YYYY-[W]WW` to Pendulum, which does not support `WW`. | Any caller configured for WEEK cannot convert canonical periods to dates; an HB resolver cannot rely on the shared parser/formatter today. | Keep the shared `TimeUnit` module unchanged for HB. The HB week helper validates canonical ISO weeks, calls `TimeUnit.parse()`, and falls back only for the known `Unsupported token: WW` error. It formats output from the ISO week-year and week number. Keep behavior regression tests and a strict-xfail round-trip sentinel; remove the fallback and sentinel when shared `TimeUnit` supports WEEK. | Fix proposed |
| HB-PERIOD-002 | `SelectedTimeUnit.to_str()` / QUARTER | Quarter periods are not formatted canonically. | `2024-Q1` formats as `2024-11`; subtracting one quarter and formatting produces `2023-44`. Pendulum interprets the `Q1`/`Q4` portions as format tokens rather than literal canonical text. | Callers that use `to_str()` receive invalid quarter strings; the HB contract and Vaskify require canonical `YYYY-Qn` periods. | Format the quarter string explicitly from the date's year and quarter number derived from its month, rather than passing `Q1`/`Q4` to Pendulum's formatter. Add regression tests for Q1–Q4 and the Q1-to-previous-year-Q4 rollover. | Fix proposed |
