# Issues

This file tracks shared source-code issues, HB integration risks, and proposed
HB behavior enhancements. Changes to shared framework code require maintainer
approval.

| ID | Area | Issue | Current behavior or context | Impact | Proposed handling | Status |
|---|---|---|---|---|---|
| HB-PERIOD-001 | `TimeUnit.parse()` / WEEK | Canonical week periods cannot be parsed. | Parsing `2024-W01` raises `ValueError: Unsupported token: WW` because `TimeUnit.parse()` passes `YYYY-[W]WW` to Pendulum, which does not support `WW`. | Any caller configured for WEEK cannot convert canonical periods to dates; an HB resolver cannot rely on the shared parser/formatter today. | Keep the shared `TimeUnit` module unchanged for HB. The HB week helper validates canonical ISO weeks, calls `TimeUnit.parse()`, and falls back only for the known `Unsupported token: WW` error. It formats output from the ISO week-year and week number. Keep behavior regression tests and a strict-xfail round-trip sentinel; remove the fallback and sentinel when shared `TimeUnit` supports WEEK. | unresolved |
| HB-PERIOD-002 | `SelectedTimeUnit.to_str()` / QUARTER | Quarter periods are not formatted canonically. | `2024-Q1` formats as `2024-11`; subtracting one quarter and formatting produces `2023-44`. Pendulum interprets the `Q1`/`Q4` portions as format tokens rather than literal canonical text. | HB cannot emit valid canonical quarter periods for the handler or Vaskify; the issue also affects year-boundary comparisons. | Keep the shared `SelectedTimeUnit.to_str()` unchanged. In the HB period helper, format quarters from the selected date's year and month-derived quarter number as `YYYY-Qn`; keep `TimeUnit` for parsing and date arithmetic. Add HB behavior tests for Q1–Q4 and Q1-to-previous-year-Q4, plus a temporary strict-xfail test for the shared quarter round-trip. Remove the HB formatter and sentinel when the shared formatter is fixed. | unresolved |
| HB-ALTINN-001 | HB / multiple active Altinn submissions | Consider giving users explicit choices when multiple active submissions exist for the same unit and period. | **Cancel** stops the current HB run. **Continue** proceeds using the latest active submission for each affected unit and period, with a message that explains this default. **Custom** lets the user choose a submission for an affected unit-period. | The approved baseline is to use `active_no_duplicates_refnr_list` unchanged with the configured form and period-specific filters, once for each comparison period. Do not change the shared helper for this proposal. Define how ties or missing `dato_mottatt` values are presented before implementation. | Proposed; requires project-owner review |
| HB-ALTINN-002 | HB / active-submission period scoping | The existing helper deduplicates active submissions by `ident`, not by period. | `active_no_duplicates_refnr_list` sorts active submissions by `dato_mottatt` and keeps the first row for each `ident`. If it receives candidates from both comparison periods in one call, it can discard one period's submission for that identifier. | The HB input may be missing one of its required comparison-period rows. | Use the helper unchanged with the configured form and period-specific filters, once per comparison period. Do not change the shared helper for HB. | Workaround approved; cover in Altinn adapter tests |
| DATA-001 | Shared data model / surrogate keys | Explore whether stable internal surrogate keys could simplify joins between related records. | Altinn relationships currently use natural keys such as `(iso_periode, skjema, ident)` and `refnr`. Tables have individual row IDs, but these do not replace the relationship keys. | Repeating composite join conditions can increase query complexity and the risk of inconsistent joins. Generating unrelated IDs per row would not solve this. | Ask maintainers to assess a persisted, stable key mapping or curated staging layer, including migration and write-path implications. Keep natural-key constraints and current HB behavior unchanged unless an approach is approved. | Proposed; requires maintainer review |
